第19章 L5 执行与闭环

学习目标：(1) 说明 L5 如何把方案包翻译成执行清单；(2) 列出 E1–E5 的职能与验证对象；(3) 解释剂量建议与认知负荷校准的关系；(4) 区分硬回滚与软重规划；(5) 描述 L5 反馈数据回到 L1 的路径。

19.1 输入契约与执行计划

L5 不重新规划，也不重新估计状态。它接收 L4 的方案包，检查门控状态，把每一步操作翻译成当下能完成的剂量，然后在执行过程中持续记录。方案包是上游的决策产物，执行清单是本级的工程产物，两者不能混为一谈。

输入字段 用途 缺失或异常时的处理
操作序列确定执行顺序、操作类型与靶点无法生成执行清单，退回 L4
剂量建议给出强度、频率、时长的初始上限按最低剂量执行并标记
成功概率作为预期基线，判断后续偏差不阻断执行，仅降低预期
时间窗安排各操作的推荐时段按常规节奏执行并标记
可读说明供执行者与临床工作者理解方案缺少说明时不启动高风险操作
门控状态决定方案能否进入执行待审或驳回时冻结
降级标记提示当前为保守方案按保守方案记录与评估

门控状态是执行的第一道闸。通过时正常校准剂量；待审时暂停高风险操作的剂量分配；驳回时拒绝执行并退回 L4。执行层不能自行解释门控，也不能用“先做一点试试”绕过冻结。

执行清单要写清三件事：今天做什么、做多久、做到什么算完成。操作标识与靶点来自方案，时长与频率来自剂量校准，完成标准来自可读说明与临床约定。三项都写清，执行数据才有对齐的基准；缺一项，后续的依从性统计就会失去参照。

19.2 内部层 E1–E5

L5 内部按“剂量校准、执行监控、反馈采集、回滚重规划、记录输出”五个阶段组织。每层有独立的输入、输出与验证对象，五层覆盖从方案包到执行记录加反馈数据的完整变换。

编号 缩写 中文全称 职能 输入 → 输出 验证对象
E1EDC执行剂量校准按当前 RES-D 校准强度、频率与时长；消费门控状态方案包与当前资源 → 执行清单剂量与负荷匹配、门控消费正确性
E2EMO执行监控跟踪完成率与脱落点，检测副作用、环境突变等异常执行清单与实时数据 → 执行状态与异常事件跟踪准确性、异常检测灵敏度
E3EFB执行反馈采集把行为与神经数据格式化为合规观测块，经 L1-B 端口送回执行数据 → 行为观测块 → L1 → L2格式合规、端口注册、时间戳准确
E4ERB执行回滚与重规划按严重度选择硬回滚或软重规划，保存中止点快照异常与状态 → 回滚信号或偏差报告严重度判定、路径选择、快照完整性
E5ELO执行记录输出封装执行时间、剂量、完成情况、异常与依从性数据执行状态与异常 → 执行记录包记录完整性、审计可追溯性

E2 与 E3 不能合并。监控回答“执行得怎么样”，反馈回答“怎么把数据送回去”。前者的验证对象是跟踪准确性，后者是格式合规性；前者随临床实践变化，后者随观测契约变化。E4 与 E2 也不能合并：监控是观测，回滚是决策，什么条件下中止的判据不应与检测标准绑在一起。

E4 独立于 E2 的另一个理由是可审计性。异常事件由 E2 记录，回滚动作由 E4 执行，两者分开后，审计能看出“检测到了什么”与“因此做了什么”是不是同一套逻辑。合并会让判断与动作混在一条日志里，事后无法复盘。

E5 独立于前四层，是因为记录不是任一层的副产物。执行状态、异常事件、依从性数据来自不同层，记录层要把它们按同一时间轴拼成一份可读、可审计的包。这份包既要给 L4 做重规划，也要给校准流程做参数更新，还要给审计接口做合规核查。

19.3 剂量建议与认知负荷校准

剂量不是把方案照抄成任务清单。它要把“做什么”翻译成“现在能做多少”。同一个 ALIGN 操作，在资源充足时可以是每周两次、每次四十分钟；在资源枯竭时只能缩成每天十分钟的微练习。剂量校准的依据是当前 RES-D 水平，不是诊断标签，也不是治疗师的习惯。

剂量维度 校准依据 示例边界
强度当前 RES-D 与情绪激活水平资源低时只做低唤醒练习
频率恢复速率与日程空隙高负荷期不安排每日新任务
时长认知负荷上限RES-D 低于 40% 时每日上限十分钟
步骤数依从性随步骤数衰减八步方案的预测依从率约 28%
环境干扰工作、家庭与数字环境的可及性干扰高的时段只安排锚定类操作

认知负荷校准的核心是把单步负荷压到患者当前资源能承受的范围。资源预算硬约束在规划层约束整条序列的总能耗，在执行层约束每一步的实际负荷。两层约束同源，但作用点不同：规划层决定“做不做”，执行层决定“做多少”。

一次具体的校准可以这样落地：RES-D 为 0.36，低于 0.40 的门槛，日上限压到十分钟。原方案要求每天三十分钟的认知重构，E1 把它拆成每天两个五分钟的微练习，保留同一靶点与同一技术，只缩短单次时长。这样既没有改变方案的结构，也没有让患者在第一天就经历一次完不成的任务。

依从性模型提供预期完成率，用于在方案设计阶段调整步骤数与剂量。八步方案预测依从率约 28%，六步方案显著更高，三步方案又更高。这个梯度意味着增加步骤并不总是增加总效果，超过患者承受能力后，多出来的步骤只会制造失败体验。

19.4 依从性、异常事件与中止回滚

执行监控跟踪三类数据：完成率、脱落点、异常事件。完成率按操作逐项记录；脱落点标记在第几步停止；异常事件包括副作用信号、情绪急剧波动、环境突变与依从性骤降。三类数据各自有时间戳，后续才能与状态序列对齐。

异常类型 严重度 响应 数据去向
依从性骤降不可恢复硬回滚：中止方案，保存中止点快照回退 L4 完整重规划
副作用信号不可恢复硬回滚：立即中止并触发安全流程执行记录与伦理审计
环境突变不可恢复硬回滚：中止当前方案，重新评估环境约束回退 L4 重规划
改善低于预期但仍在轨道可恢复软重规划：不中止，只调整后续阶段参数偏差报告与修正约束送 L4
单步未完成轻微记录脱落点，下一步降低剂量依从性数据与剂量模型

硬回滚与软重规划的区别是“要不要停下来”。硬回滚面对不可恢复的异常，必须中止当前方案，保存中止点，退回 L4 完整重规划；软重规划面对可恢复的偏差，不中止当前阶段，只把偏差数据与修正约束送给 L4，让后续阶段调整参数。严重度由监控层判定，不由执行者凭感觉选择。

回滚不是失败，是正常控制行为。L4 在重规划时不应因回滚历史而系统性收窄搜索空间，除非回滚原因明确指向某类操作的风险。把回滚记成失败，会让系统倾向于“硬撑到底”，这恰恰是最危险的行为。

中止判据要在执行前写清，不能等异常出现后再临时商量。哪一类副作用必须立即停、完成率连续几次低于多少算骤降、环境突变达到什么程度需要重评估，都要在方案包或执行清单里有明确条目。判据前置，执行者才不需要在压力下临场解释。

19.5 闭环 L5 → L1：反馈数据如何回到观测

执行产生两类反馈：行为数据与神经数据。行为数据包括 EMA 记录、作业完成率、暴露练习的主观困扰评分；神经数据在具备采集条件时包括睡眠、心率变异性与活动量。这些数据不能直接塞进 L2，必须先变成合规观测。

反馈路径是 L5 到 L1-B 行为端口，注册为行为观测条目，生成行为观测块，再经 L1 汇总进入 L2 融合。走端口而不是走侧信道，是为了让反馈数据与常规观测使用同一套索引、值域、不确定度与降级编码。否则 L2 会收到一批格式不同、语义不明的数据，融合结果无法审计。

回路 路径 时间尺度 主要消费者
控制回路L5 → L1 → L2 → L3 → L4 → L5天到周L4 动态重规划
学习回路L5 → L1 → L2 → L3 校准流程月到疗程PSE-C 参数与权重更新
审计回路L5 → 执行记录包 → 审计接口事件驱动伦理与质量审计

控制回路让干预效果实时进入下一轮决策。执行偏差出现后，新的行为观测进入 L2，后验更新，L3 重新预测，L4 调整方案。学习回路把同一批数据以更慢的节奏送进校准流程，更新参数后验与模型权重。两条回路使用同一批数据，但时间尺度与消费者不同，不能互相替代。

两条回路都需要稳定的时间戳与统一编码。时间戳错位会让 L2 把旧反馈当成新观测，编码不统一会让融合层无法判断不确定度。闭环的质量首先取决于这两件基础工作，而不是取决于反馈数据的总量。

闭环的反馈数据仍然是理论构成的观测。患者报告“今天焦虑减轻”，这句话经语义端口编译后才成为观测块；编译规则本身带有理论假设。闭环能提高预测精度，但不能被当作独立于框架的外部验证。

19.6 执行记录包与审计接口

执行记录包是 L5 的最终产物，也是 L4 重规划与校准流程的输入。它要完整到能复盘每一次操作，又要简洁到能被人读懂。记录包不追求“好看”，只追求“可追溯”。

记录字段 内容 审计用途
操作标识与靶点第几步、操作类型、靶点坐标确认执行是否偏离方案
计划与实际时间推荐时段与真实执行时刻判断时间窗是否被遵守
计划剂量与实际剂量强度、频率、时长识别剂量校准偏差
完成情况完成、部分完成、未完成、脱落计算依从率与脱落点
异常事件类型、严重度、发生时刻、处置复盘回滚或重规划依据
环境干扰工作、家庭、数字环境的突发变化解释偏差的外部原因
门控与审批引用门控状态、审批编号、否决记录伦理合规核查
中止点快照回滚时的状态、已执行步骤、未执行步骤支持 L4 从断点重规划

记录包同时服务三个消费者：L4 用中止点与偏差报告做重规划；校准流程用依从性与剂量完成情况更新参数；审计接口用门控引用与异常记录核查合规。三个消费者读同一份记录，但各有自己的读取口径，记录本身不能被任何一方改写。

审计接口的最低要求是“不伪造、不静默、不级联放大”。降级时不能填虚假的成功概率或依从率；降级必须在记录中显式标记；一级降级不能触发另一级降级。三条规则看起来是工程细节，实际决定了闭环数据能不能被信任。
