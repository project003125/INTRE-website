## 二、问题一：UPLP 被错误描述为语法所有者（已修复）

### 2.1 问题定性

**严重程度**：高 — 属于事实性术语错误

M-R-D-S 状态语法与 G-M-A-R 操作语法的定义权归属 **IODS（INTRE 本体定义系统，L0 层）**，而非 UPLP。UPLP（统一心理语言端口，L1-S）是语义观测端口，其定位是 **消费 IODS 定义的语法** 进行语义编译，而非语法的所有者。

权威依据：
- 01-M-02 §1.1："IODS 覆盖原 UPLP-A 定义功能的全部构成"
- 01-M-02 §1.3：语义编译流水线等运行时内容从 UPLP-A 移出，归入 L1-S
- 12-A-14 A5：IODS 保留 System 名，因其是对外独立系统（P7 两系统之一）

### 2.2 问题清单与修复情况

| # | 文件 | 行号 | 原文 | 修复后 | 状态 |
|---|------|------|------|--------|------|
| 1 | `02-ia.md` | §3.1 页面树 | `/uplp/` 下子项：`M-R-D-S 状态语法 / G-M-A-R 操作语法 / PCUI / PSA / PSL` | 改为：`语义编译流水线 / PCUI 映射 / PSA 标注体系 / PSL 词汇库`，并加注语法归属 IODS | ✅ 已修复 |
| 2 | `02-ia.md` | §3.2 URL 映射表 | UPLP 内容定位："语义通道：M-R-D-S 状态语法、G-M-A-R 操作语法" | 改为："语义端口（L1-S）：语义编译流水线、PCUI 映射、PSA 标注体系、PSL 词汇库" | ✅ 已修复 |
| 3 | `02-ia.md` | §9.1.2 UPLP 模块页规格 | 内容区块含"状态语法 M-R-D-S 四元组""操作语法 G-M-A-R 四元组" | 重写为：核心功能（语义编译流水线）、标注体系（PSA）、子概念（PCUI/PSL，定义归属 IODS）、语法引用（消费 IODS 语法） | ✅ 已修复 |
| 4 | `10-link-system-plan.md` | §1.1 页面清单 | UPLP 内容定位："语义通道：M-R-D-S 状态语法、G-M-A-R 操作语法、PCUI/PSA/PSL" | 改为："语义端口（L1-S）：语义编译流水线、PCUI 映射、PSA 标注体系、PSL 词汇库" | ✅ 已修复 |

### 2.3 修复原则

1. **UPLP 定位修正**：从"语义通道"改为"语义端口（L1-S）"，与 06-S-02 v2.9.0 的 Port 命名一致
2. **语法归属澄清**：M-R-D-S / G-M-A-R 不再列为 UPLP 子内容，改为"消费 IODS 定义的语法"
3. **运行时内容前置**：将语义编译流水线、PSA 标注体系等 UPLP 实际核心功能前置
4. **PCUI/PSL 归属说明**：注明其定义归属 IODS，UPLP 是使用端

## 三、问题二："五大模块"表述与最新架构不一致（待决策）

### 3.1 问题定性

**严重程度**：中 — 属于架构叙事层面的不一致，非事实错误

文档中多处使用"五大模块"（UPLP / UNIP / UBMP / PSE / REVER）的并列表述，这与 12-A-14 确立的 **"双系统 + 三端口 + 护栏"** 最新架构存在层级混淆：

| 最新架构层级 | 组件 | 定位 |
|-------------|------|------|
| **L0 本体定义系统** | IODS | 独立系统，定义坐标系/词汇/语法/结构约束 |
| **L1-L5 计算引擎** | PSE | 独立系统，承载全部运行时计算 |
| └─ L1 观测端口 | UPLP / UBMP / UNIP | PSE 内部的三个感知端口（Port） |
| **伦理护栏** | REVER | 独立门控系统，护栏角色 |

"五大模块"将 IODS 排除在外，且把 PSE（系统级）与三个 Port（组件级）、REVER（护栏级）并列，存在架构层级扁平化问题。

### 3.2 问题清单

| # | 文件 | 位置 | 原文 | 说明 |
|---|------|------|------|------|
| 1 | `02-ia.md` | §1.1 总览图 | 2D 网站列出 UPLP/UNIP/UBMP/PSE/REVER 共 5 项 | 缺 IODS |
| 2 | `02-ia.md` | §3.1 页面树 | "五大模块卡片网格（UPLP/UNIP/UBMP/PSE/REVER）" | 五模块并列表述 |
| 3 | `02-ia.md` | §3.2 URL 映射表 | 首页定位含"五大模块卡片" | 同上 |
| 4 | `02-ia.md` | §3.4 导航结构 | 顶部导航 8 项 + 页脚 Modules 列均为 5 项 | 缺 IODS |
| 5 | `01-prd.md` | 附录 B | 页脚 Sitemap："Modules: UPLP / UNIP / UBMP / PSE / REVER" | 同上 |
| 6 | `10-link-system-plan.md` | §1.1 页面清单 | 首页定位含"五大模块卡片" | 同上 |

### 3.3 建议修改方向（待产品决策）

**方案 A：导航新增 IODS，Modules 列重命名为分层结构**

- 顶部导航新增 IODS 入口（第 2 位，在 UPLP 之前）
- 页脚 Modules 列改为 System 列，分两层：
  - Systems: IODS / PSE / REVER
  - Ports: UPLP / UBMP / UNIP
- 首页"五大模块卡片"改为"双系统 + 三端口 + 护栏"的分层展示

**方案 B：维持五模块并列，仅新增 IODS 到导航**

- 顶部导航加 IODS，变为 9 项
- 首页卡片变为 6 张
- 不调整架构叙事层级

**方案 C：维持现状，仅在文档中加注**

- 所有"五大模块"表述后加注释："按网站已上线结构，对应 IODS+PSE+REVER 三系统 + UPLP/UBMP/UNIP 三端口"
- 导航结构不调整

> **建议**：采用方案 A。理由：与 12-A-14 的最新架构完全对齐，避免用户认知混淆；IODS 作为 L0 本体定义系统，其地位应在导航中体现。

## 四、问题三：导航结构中缺少 IODS（待决策）

### 4.1 问题定性

**严重程度**：中高 — 核心系统在信息架构中完全缺位

整个 `docs/` 目录中 **零次** 出现"IODS"。作为 P7 决策确立的两大系统之一（IODS + PSE），IODS 在 3D Hero 的信息架构、导航结构、页面树中完全缺失。

### 4.2 问题清单

| # | 缺失位置 | 所在文件 | 说明 |
|---|---------|----------|------|
| 1 | 顶部导航栏 | `02-ia.md` §3.4、§5.2.1 | 8 项导航无 IODS |
| 2 | 页脚 Sitemap | `02-ia.md` §3.4、`01-prd.md` 附录 B | Modules 列 5 项无 IODS |
| 3 | 2D 网站页面树 | `02-ia.md` §3.1 | 无 /iods/ 页面 |
| 4 | URL 映射表 | `02-ia.md` §3.2、`10-link-system-plan.md` §1.1 | 无 IODS 页面 |
| 5 | 首页卡片网格 | `02-ia.md` §9.1.1 | 五大模块无 IODS |
| 6 | 3D Hero 顶部导航 | `03-wireframe.md` §1.1 | 顶栏 8 项无 IODS |
| 7 | 术语表 | `09-glossary.md` §6 通道色术语 | 无 IODS 词条 |
| 8 | 链接系统规划 | `10-link-system-plan.md` §1.3 | 导航结构无 IODS |

### 4.3 影响分析

1. **架构叙事不完整**：用户无法从 3D Hero 或 2D 网站导航中了解 IODS 的存在
2. **术语认知偏差**：用户可能认为 M-R-D-S / G-M-A-R 语法是 UPLP 或 PSE 的一部分（已在问题一中部分修复）
3. **论文引用缺失**：IODS 作为核心理论文档，在官网无对应入口

### 4.4 建议（待产品决策）

1. **新增 IODS 页面** `/iods/`：展示本体定义系统的定位、构成（42 维坐标系 / 词汇库 / 概念映射 / 结构约束）、与 PSE 的关系
2. **导航插入 IODS**：顶部导航在 UPLP 之前插入 IODS，或放在 PSE 之前（作为"定义系统"）
3. **首页卡片重组**：按"双系统 + 三端口 + 护栏"分层展示
4. **3D Hero 同步更新**：顶部导航、底部信息条同步新增 IODS 入口
