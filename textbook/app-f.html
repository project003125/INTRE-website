附录F 逻辑指纹与 PCUI JSON

逻辑指纹是判断两份解析是否指向同一心理实体的最小结构。它不记录全部描述，只记录四组互斥关系：谁参与、消耗什么、哪层是根源、对应什么操作。四组指纹各自回答一个问题，不依赖其他组的答案。

F.1 四组逻辑指纹

指纹判定问题取值形式示例
模块指纹涉及哪些模块，角色如何有序对集合，角色为核、参与、背景M4 核，M2 参与，M6 输出
资源指纹消耗或保护哪类资源，方向如何RES-D 与 RES-B 的加减集合，可缺失RES-D 减，RES-B 加
层级指纹表现层与根源层是什么，方向如何表现层取 DSP，根源层取 STR，方向指向根源DSP-B 表现，STR-C 根源
操作指纹优先操作是什么，顺序如何算子序列，须符合靶点矩阵GATE−，MODULATE+，RELINK

四组指纹分别正交：模块指纹只回答参与与角色，资源指纹只回答资源类型与方向，层级指纹只回答表现与根源，操作指纹只回答操作与顺序。正交不等于测量独立，它指判定问题不重叠。

四组指纹不一致时，先检查是否在比较不同的解析层级。模块指纹的分歧常来自角色权重，资源指纹的分歧常来自时间窗，层级指纹的分歧常来自表现与根源的倒置，操作指纹的分歧常来自主靶点判断。分歧记录在条目中，不强行合并为一个“正确解析”。

编码版本记录变更范围。新增同义词只动映射层，坐标调整动核心层，模块签名变化动标识符。读者通过版本号与变更说明，可以判断一个旧条目还能不能直接引用。

F.2 PCUI 字段

PCUI 编码把概念固定为一个标识符，格式为功能码、框架、版本、序号与模块签名。模块签名用角色标签：C 核心，I 受冲击，S 支撑，T 触发，O 输出。一个编码至少包含一个 C 标签；缺 C 的条目无法定位核心失调位点。

字段内容用途
pcui完整编码与模块签名唯一标识与检索
core_definition理论中立的功能定义跨流派共识
coordinates模块、层级、维度与参数范围坐标定位
fingerprints四组逻辑指纹同一性判定
school_views各流派解释与证据等级保留分歧
intervention_sequence操作序列与前提条件L4 规划输入
validation共识度、验证数据、异议证据管理

F.3 JSON 示例

JSON 的作用是让条目可机读、可比较、可版本化。四组指纹进入索引，坐标与操作序列进入检索，伦理标注进入门控。读者看到的解释文本可以不同，底层字段必须一致。
